# Font Copy Master

> 上传一张美术字参考图，拆解它的字体骨架、字形改造、排版和视觉效果，生成可直接用于 **GPT Image 2** 的中文提示词。

不需要会认字体，也不需要自己研究描边、渐变、立体感和材质参数。把截图交给 Codex，再告诉它你真正想写的文案即可。

## 它能做什么？

### 1. 从截图反推美术字效果

Skill 会观察并整理：

- 原图中的文字与语种
- 可能使用的字体类别和候选字体
- 笔画、切角、连笔、拉伸等字形改造
- 字距、行距、对齐和整体构图
- 渐变、描边、阴影、金属、发光等效果层次
- 背景、人物、图标等不应进入提示词的元素

字体候选是根据可见特征做出的推测，不会把不确定的字体名称说成确定答案。

### 2. 把效果换到你的文案上

分析完成后，你只需提供真正想生成的文字。Skill 会保留文案原样，并根据字数调整排版，输出完整的终版提示词。

### 3. 把好用的字效存成案例

只有在你明确确认后，Skill 才会归档：

- 最终提示词
- 字体与效果分析
- 适用语种、风格和效果分类
- 原始参考图

下次遇到相近需求时，可以直接从案例库查找和复用。

## 三步开始使用

### 第一步：上传参考图

在 Codex 对话中上传一张美术字截图，然后说：

```text
分析这张图里的美术字，并生成 GPT Image 2 提示词。
```

也可以直接说：

```text
试试这个字体。
```

### 第二步：提供目标文案

收到分析和原文提示词后，回复你真正想写的内容：

```text
我的文案是：周末一起出发
```

需要分行时直接换行：

```text
周末一起
出发
```

### 第三步：决定是否归档

对效果满意后回复：

```text
把这个字体效果存档。
```

Skill 会返回案例编号和本地存档位置。没有明确确认时，不会自动保存参考图。

## 你会得到什么？

每次分析通常包含以下内容：

1. **文字与语种**：识别原图文字及文字系统
2. **字体推测**：候选字体、字体类别、置信度和判断依据
3. **字形改造**：说明原字如何被重新设计
4. **排版**：字距、行距、对齐与层级
5. **效果层次**：从字面填充到描边、阴影和材质逐层拆解
6. **应排除元素**：防止模型把背景、图标或其他文字画进去
7. **终版提示词**：只描述文字及其附着效果，默认要求透明背景

提示词会强调文字必须逐字准确，并排除人物、场景、Logo、水印和无关装饰。

## 存档与隐私

案例默认保存在 Skill 内部的 `library` 目录：

```text
font-effect-prompt-builder/library/
├── index.jsonl
└── cases/
    └── <case_id>/
        ├── case.md
        └── reference.png
```

请注意：

- 存档会保留原始参考图。
- 本地归档不会自动上传到网络。
- 如果把案例提交到公开 GitHub 仓库，参考图也会公开。
- 上传不属于你的图片前，请确认你有权使用和公开它。

## 能力边界

- 当前版本只生成提示词，不直接生成图片。
- 截图通常不足以百分之百确定具体字体，因此结果会区分“可观察特征”和“字体候选”。
- 文字过小、模糊、被遮挡时，可能需要你补充原始文字。
- 最终图片中文字是否完全正确，仍取决于图像模型的文字渲染能力。
- 提示词只保留文字本体及其附着效果，不会自动复制原图中的人物、背景和场景物件。

## 常见问题

### 一定要知道字体名称吗？

不需要。Skill 会优先描述可观察的笔画和效果，即使无法锁定字体，也能生成可执行的提示词。

### 没有目标文案也能用吗？

可以。Skill 会先根据原图文字输出一版完整提示词，等你提供目标文案后再生成终版。

### 为什么默认使用透明背景？

透明背景更适合把美术字继续用于海报、封面、视频和 UI。模型无法输出透明背景时，提示词会要求使用单一高对比纯色作为备用。

### 会自动保存我的图片吗？

不会。只有你明确要求归档，并且参考图是可读取的本地文件时，才会保存案例。
